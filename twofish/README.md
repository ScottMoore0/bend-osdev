# bend-osdev-twofish

Twofish (the AES submission), a 128-bit block cipher with 128-, 192- or 256-bit keys, on cipher-modes' `CmBlock`, so it plugs into every mode of cipher-modes (CBC, XTS, CCM, CMAC) as their template arguments.

The directory is `twofish` and the entry file `twofish/twofish.bend`; the hub name is `bend-osdev-twofish`. It is one of the packages split from bend-osdev-legacy-ciphers@0.1.0.0, which they supersede (that version stays on the hub as it was): cipher-core (what the ciphers share, and the 64-bit modes) and one package per cipher.

None of the code here is constant-time (see Side channels).

## Specifications

Written from the public specification only; no implementation's source was read.

* **Twofish:** B. Schneier, J. Kelsey, D. Whiting, D. Wagner, C. Hall,
  N. Ferguson, *Twofish: A 128-Bit Block Cipher* (AES submission, 1998): q0
  and q1 from their 4-bit tables, the MDS and RS matrices, h, g, F, the key
  schedule, and the zero padding of a shorter key (section 4.3). Test vectors:
  the paper's three vectors (128-, 192- and 256-bit keys).

The test vectors were checked against the model in `ref/model.py` before they became laws or `check.bend` lines.

The generated regions lie between `# BEGIN GENERATED by gen/<script>.py: <name>` and `# END GENERATED: <name>` lines; everything outside them is written by hand.

## Public interface

The key type is opaque: built by the cipher's `key` functions from the raw key, used only through the cipher's defs. Every fallible function answers `Result<&2, &2, LcError, A>` with cipher-core's `LcError`: `LcBadKeyLength{got}` for a key of a length the cipher does not take (16, 24 or 32 (1 to 32 with `key_padded`) bytes).

**`twofish.bend`**

| Def / type | Meaning |
|---|---|
| `LcTwofishKey`, `LcTwofish.key(o)` | 16, 24 or 32 bytes; opaque |
| `LcTwofish.key_padded(o)` | 1 to 32 bytes, zero-padded to the next size as the paper says |
| `LcTwofish.encrypt(k, b)`, `LcTwofish.decrypt(k, b)` | one `CmBlock` |

Everything else (`tf.*`, `LcTfOp`, `LcTfTabs`) is internal.

## With cipher-modes

The cipher has exactly the shape cipher-modes' modes take (see cipher-modes'
README): a key type, and `encrypt` and `decrypt` from key and `CmBlock` to
`CmBlock`. So every mode there runs over it unchanged:

```
import ../cipher-modes/cbc.bend as CB
import ../cipher-modes/xts.bend as XT
import ../twofish/twofish.bend as C

CB.Cbc.encrypt(~C.LcTwofishKey, ~C.LcTwofish.encrypt, k, iv, m)
XT.Xts.decrypt(~C.LcTwofishKey, ~C.LcTwofish.encrypt, ~C.LcTwofish.decrypt, k1, k2, i, c)
```

and likewise CCM and CMAC. cipher-modes' round-trip laws take the cipher's
inversion at the law's key as a hypothesis; this package's `twofish_round_trip`
gives it for every key, and bend-osdev-cm-instances states and proves those
mode laws at this cipher (`twofish_cbc_round_trip`, `twofish_xts_round_trip`, ...),
in a package of its own so that importing this package's proofs (crypto
does) does not take in cipher-modes' too. crypto's ECB, CBC, CTR, PCBC, LRW
and CBC-CS3 run over it as well (crypto's `LAWS_lc.bend`).

## Extension points

* **Any mode over the cipher:** it is cipher-modes' template arguments (and crypto's); a new mode takes `~K`, `~enc`, `~dec` and never looks inside the key.
* **Key sizes and options are parameters** where the specification gives a choice: the key's length picks the variant, and `key_padded` pads a shorter key as the paper says.
* **Replaceable internals:** the key type is opaque, so the cipher's representation (its round keys, its tables) can change without touching a caller. The cipher is a list of invertible steps, decryption the steps undone in reverse order; a faster implementation (bit-sliced S-boxes, combined tables, hardware instructions) can go behind the same defs, tied to these by the vectors and the differential test.

## Laws

`LAWS.bend` (2 laws).

**For every input:**

* `twofish_round_trip`, `twofish_round_trip_dual`: for every Twofish key (every key size) and every 128-bit block, decryption undoes encryption and encryption undoes decryption.

The Twofish paper's vectors run compiled in `check.bend` instead of being laws: one Twofish key schedule takes more than 2.5 GB in the checker, near a check process's limit.

How the round trips are proved: the cipher is a list of steps, each undone by its inverse whatever its round function or key is, so no proof evaluates the cipher. Here each step is undone: a round whatever F is (by XOR, cipher-core's `u32_xor_cancel`, and the 1-bit rotations undone, `rotl1_rotl31`, `rotl31_rotl1`), the whitening by XOR, the byte swaps by themselves (`bswap_bswap`). cm-instances turns `twofish_round_trip` into cipher-modes' CBC and XTS round trips at this cipher.

The proofs need nothing from another package beyond its public interface and laws: cipher-core's laws (above).

## Tests

* `check.bend` runs the paper's three vectors both ways (encryption, then decryption back), and the cipher through cipher-modes' CBC over 32 KB both ways.
* `ref/run.sh` compares Twofish against `ref/model.py` alone (neither `cryptography` nor `openssl` has it), on random keys, blocks and messages, each a block both ways and a CBC message both ways. **`ref/model.py` was written here from the specification, by the same author as this package**, and is first checked against the specification's published vectors. `run.sh` exits 77 when `python3` is missing.

## Speed

Measured on Bend 2.0.37, native builds (`bend file.bend -o prog`), WSL2, before the split (the code is unchanged):

| Run | Time | Notes |
|---|---|---|
| Twofish-128 | 130 us per 16-byte block | key-dependent S-boxes through q0, q1 and MDS tables |
| Twofish-128, CBC through cipher-modes, 1 MB both ways | 20.1 s, 226 MB peak |  |

The cipher builds its lookup tables when its key is made and keeps them in the key (Bend 2.0.37 recomputes a table def at every call). Messages have no length limit beyond memory: every loop over blocks or bytes is a tail call.

## Side channels

The S-boxes are table lookups (trees walked by the bits of a secret index). None of this is constant-time, and Bend's runtime promises nothing about running time anyway. Do not use this package where timing attacks matter.

## Dependencies

`DEPS`: `bytes` (`Octets`); `cipher-modes` (its open 128-bit block `CmBlock`, so the cipher plugs into its modes; the tests use its CBC). Only `cipher-modes.bend` and `cbc.bend` are imported, not cipher-modes' AES, so this package does not pull in bend-collections; `cipher-core` (the error type `LcError`, the word helpers and tables the cipher is built from, and its laws in the proofs: XOR undone and the rest).

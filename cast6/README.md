# bend-osdev-cast6

CAST-256 (CAST6, RFC 2612), a 128-bit block cipher with keys of 128 to 256 bits, on mode-core's `CmBlock`, so it plugs into every 128-bit mode (the cbc, xts, ccm and cmac packages) as their template arguments. It uses CAST-128's S-boxes and round functions from the cast5 package.

The directory is `cast6` and the entry file `cast6/cast6.bend`; the hub name is `bend-osdev-cast6`. It is one of the packages split from bend-osdev-legacy-ciphers@0.1.0.0, which they supersede (that version stays on the hub as it was): cipher-core (what the ciphers share, and the 64-bit modes) and one package per cipher.

None of the code here is constant-time (see Side channels).

## Specifications

Written from the public specification only; no implementation's source was read.

* **CAST-256 (CAST6):** RFC 2612, *The CAST-256 Encryption Algorithm*
  (1999): the quad-rounds Q and QBAR, f1, f2, f3 over CAST-128's S1 to S4
  (from the cast5 package), and the key schedule (the octave W, Tm and Tr);
  keys of 128 to 256 bits in 32-bit steps. Test vectors: RFC 2612, Appendix
  A (128-, 192- and 256-bit keys).

The test vectors were checked against the model in `ref/model.py` before they became laws or `check.bend` lines.

## Files

| File | Holds |
|---|---|
| `cast6.bend` | CAST-256 |
| `gen/vectors.py` | the generator of the vector laws in `LAWS.bend`, their proofs in `PROOF.bend`, and `check.bend`'s `main` and expected `#|` lines, from `ref/model.py`; `python3 gen/vectors.py` rewrites them, `--check` checks they are up to date |
| `ref/` | the differential test (`run.sh`, `gen.py`, `model.py`) |

The generated regions lie between `# BEGIN GENERATED by gen/<script>.py: <name>` and `# END GENERATED: <name>` lines; everything outside them is written by hand. After changing the vector laws, run `gen/vectors.py`.

## Public interface

The key type is opaque: built by the cipher's `key` functions from the raw key, used only through the cipher's defs. Every fallible function answers `Result<&2, &2, LcError, A>` with cipher-core's `LcError`: `LcBadKeyLength{got}` for a key of a length the cipher does not take (16 to 32 in steps of 4 bytes).

**`cast6.bend`**

| Def / type | Meaning |
|---|---|
| `LcCast6Key`, `LcCast6.key(o)` | 16, 20, 24, 28 or 32 bytes; opaque |
| `LcCast6.encrypt(k, b)`, `LcCast6.decrypt(k, b)` | one `CmBlock` |

Everything else (`c6.*`, `LcCast6Ks`, `LcCast6Op`, `LcCast6Kst`) is
internal.

## With the modes

The cipher has exactly the shape the 128-bit modes take (see mode-core's
README): a key type, and `encrypt` and `decrypt` from key and `CmBlock` to
`CmBlock`. So every mode there runs over it unchanged:

```
import ../cbc/cbc.bend as CB
import ../xts/xts.bend as XT
import ../cast6/cast6.bend as C

CB.Cbc.encrypt(~C.LcCast6Key, ~C.LcCast6.encrypt, k, iv, m)
XT.Xts.decrypt(~C.LcCast6Key, ~C.LcCast6.encrypt, ~C.LcCast6.decrypt, k1, k2, i, c)
```

and likewise CCM and CMAC. The modes' round-trip laws take the cipher's
inversion at the law's key as a hypothesis; this package's `cast6_round_trip`
gives it for every key, and bend-osdev-cm-instances states and proves those
mode laws at this cipher (`cast6_cbc_round_trip`, `cast6_xts_round_trip`, ...),
in a package of its own so that importing this package's proofs (crypto
does) does not take in the modes' too. crypto's ECB, CBC, CTR, PCBC, LRW
and CBC-CS3 run over it as well (crypto's `LAWS_lc.bend`).

## Extension points

* **Any mode over the cipher:** it is the modes' template arguments (and crypto's); a new mode takes `~K`, `~enc`, `~dec` and never looks inside the key.
* **Key sizes and options are parameters** where the specification gives a choice: any key of 128 to 256 bits in 32-bit steps.
* **Replaceable internals:** the key type is opaque, so the cipher's representation (its round keys, its tables) can change without touching a caller. The cipher is a list of invertible steps, decryption the steps undone in reverse order; a faster implementation (bit-sliced S-boxes, combined tables, hardware instructions) can go behind the same defs, tied to these by the vectors and the differential test.

## Laws

`LAWS.bend` (3 laws).

**For every input:**

* `cast6_round_trip`, `cast6_round_trip_dual`: for every CAST-256 key (every key size) and every 128-bit block, decryption undoes encryption and encryption undoes decryption.

**Vectors** (proved by computation): the refusal of an 18-byte key. RFC 2612's vectors run compiled in `check.bend` instead: they run past the `--verdict` kernel's evaluation budget.

How the round trips are proved: the cipher is a list of steps, each undone by its inverse whatever its round function or key is, so no proof evaluates the cipher. Here each step of a quad-round is undone by itself (by XOR, cipher-core's `u32_xor_cancel`), so QBAR undoes Q, whatever f1, f2 and f3 are. cm-instances turns `cast6_round_trip` into cbc's CBC and XTS round trips at this cipher.

The proofs need nothing from another package beyond its public interface and laws: cipher-core's laws (above).

## Tests

* `check.bend` runs RFC 2612's three vectors both ways (encryption, then decryption back), and the cipher through cbc's CBC over 32 KB both ways.
* `ref/run.sh` compares CAST-256 against `ref/model.py` alone (neither `cryptography` nor `openssl` has it), on random keys, blocks and messages, each a block both ways and a CBC message both ways. **`ref/model.py` was written here from the specification, by the same author as this package**, and is first checked against the specification's published vectors. `run.sh` exits 77 when `python3` is missing.

## Speed

Measured on Bend 2.0.37, native builds (`bend file.bend -o prog`), WSL2, before the split (the code is unchanged):

| Run | Time | Notes |
|---|---|---|
| CAST-256 (128-bit key), CBC through cbc, 256 KB both ways | 1.8 s, 58 MB peak |  |

The cipher builds its lookup tables when its key is made and keeps them in the key (Bend 2.0.37 recomputes a table def at every call). Messages have no length limit beyond memory: every loop over blocks or bytes is a tail call.

## Side channels

The S-boxes are table lookups (trees walked by the bits of a secret index). None of this is constant-time, and Bend's runtime promises nothing about running time anyway. Do not use this package where timing attacks matter.

## Dependencies

`DEPS`: `bytes` (`Octets`); `mode-core` (its open 128-bit block `CmBlock`, so the cipher plugs into the modes); `cbc` (the tests only: CBC over the cipher); `cipher-core` (the error type `LcError`, the word helpers and tables the cipher is built from, and its laws in the proofs: XOR undone and the rest); `cast5` (CAST-128's S-boxes S1 to S4 and round functions f1, f2, f3, which CAST-256 uses).

# bend-osdev-rc4

RC4 (RFC 6229's description) and RC4-drop[n] (RFC 4345), a stream cipher, with a streaming interface (`start`, `update`).

The directory is `rc4` and the entry file `rc4/rc4.bend`; the hub name is `bend-osdev-rc4`. It is one of the packages split from bend-osdev-legacy-ciphers@0.1.0.0, which they supersede (that version stays on the hub as it was): cipher-core (what the ciphers share, and the 64-bit modes) and one package per cipher.

**RC4 is broken and RFC 7465 forbids it in TLS**: use it only to interoperate with what already uses it. None of the code here is constant-time (see Side channels).

## Specifications

Written from the public specification only; no implementation's source was read.

* **RC4:** the key-scheduling and output algorithms as RFC 6229, *Test
  Vectors for the Stream Cipher RC4* (2011), describes them, with its test
  vectors for the key 0x0102030405 at every offset it lists; RFC 4345 for
  RC4-drop[n]. RFC 7465, *Prohibiting RC4 Cipher Suites* (2015), forbids it
  in TLS.

The test vectors were checked against the model in `ref/model.py` and Python's `cryptography` before they became laws or `check.bend` lines.

## Files

| File | Holds |
|---|---|
| `rc4.bend` | RC4, streaming |
| `gen/vectors.py` | the generator of the vector laws in `LAWS.bend`, their proofs in `PROOF.bend`, and `check.bend`'s `main` and expected `#|` lines, from `ref/model.py`; `python3 gen/vectors.py` rewrites them, `--check` checks they are up to date |
| `gen/proof.py` | the generator of `PROOF.bend`'s region "bits" (the low byte of a XOR, on the words' 32 bits); the same two modes |
| `ref/` | the differential test (`run.sh`, `gen.py`, `model.py`) |

The generated regions lie between `# BEGIN GENERATED by gen/<script>.py: <name>` and `# END GENERATED: <name>` lines; everything outside them is written by hand. After changing the vector laws, run `gen/vectors.py`.

## Public interface

The key type is opaque: built by the cipher's `key` functions from the raw key, used only through the cipher's defs. Every fallible function answers `Result<&2, &2, LcError, A>` with cipher-core's `LcError`: `LcBadKeyLength{got}` for a key of a length the cipher does not take (1 to 256 bytes).

**`rc4.bend`**

| Def / type | Meaning |
|---|---|
| `LcRc4State` | the state (S, i, j); opaque |
| `LcRc4.start(key)` | the state after the key schedule, for a key of 1 to 256 bytes |
| `LcRc4.start_drop(key, n)` | the same, with the first n keystream bytes dropped (RC4-drop[n]) |
| `LcRc4.update(st, m) -> LcRc4Out` | the next piece of data, encrypted or decrypted (the same thing), and the state after it |
| `LcRc4Out{state, data}`, `LcRc4.out_state(o)`, `LcRc4.out_data(o)` | the result (open type) |
| `LcRc4.crypt(key, m)` | the data under a key, in one call |
| `LcRc4.keystream(st, n)` | the next n keystream bytes |

Everything else (`rc4.*`, `LcRc4Step`, `LcRc4Run`) is internal.

## Streaming

RC4 is a stream: `start`, then `update` once per piece, carrying the state; the law `rc4_streaming_*` says pieces give the output of the whole. crypto's `inst_rc4.bend` makes it an instance of crypto's stream-cipher interface.

## Extension points

* **Key size and drop:** any key of 1 to 256 bytes, and RC4-drop[n] by
  `start_drop`.
* **Streaming:** `start`, then `update` once per piece, carrying the state;
  the law `rc4_streaming_*` says pieces give the output of the whole.
* **Replaceable internals:** the state is opaque (its S is a table of
  cipher-core's `LcTab`), so a faster representation can go behind the same
  defs, tied to this one by RFC 6229's vectors and the differential test.
* **Not here yet:** RC4's variants beyond drop[n].

## Laws

`LAWS.bend` (4 laws).

**For every input:**

* `rc4_involution`: from any state, the cipher applied twice gives the data
  back, for all data;
* `rc4_streaming_data`, `rc4_streaming_state`: RC4 over `a ++ b` is RC4 over
  `a`, then over `b` from the state after `a`.

**Vectors** (proved by computation): the refusal of an empty key. RFC 6229's
vectors run compiled in `check.bend` instead: the checker proves them, but
RC4's 256-step key schedule runs past the `--verdict` kernel's evaluation
budget (128 steps do not).

How they are proved: the tail-recursive loop is proved equal to its
structural form, and XORing the same keystream twice gives the data back
(cipher-core's `u32_xor_cancel`, with the low byte of a XOR depending only on
the low bytes, `gen/proof.py`); streaming follows from the keystream of
`a ++ b` being that of `a`, then of `b` from the state after `a`, with bytes'
laws for `Octets` appends (`octets_to_of`, `octets_of_to`,
`octets_of_list_idempotent`, `octets_append_list`).

The proofs need nothing from another package beyond its public interface and laws: cipher-core's laws (above) and bytes' `octets_to_of`, `octets_of_to`, `octets_of_list_idempotent`, `octets_append_list`.

## Tests

* `check.bend` runs RFC 6229's eighteen offsets for its 40-bit key, RC4 in
  three pieces, and RC4-drop[1536].
* `ref/run.sh` compares RC4 (key lengths 1 to 256, data in two pieces, and drop[n]) against Python's `cryptography` (at the key sizes it accepts, nothing dropped) and `ref/model.py`, on random keys, blocks and messages, each a stream in two pieces, with nothing or n bytes dropped. **`ref/model.py` was written here from the specification, by the same author as this package**, and is first checked against the specification's published vectors. When `cryptography` is missing, `run.sh` compares with the model alone and says so; it exits 77 only when `python3` is missing.

## Speed

Measured on Bend 2.0.37, native builds (`bend file.bend -o prog`), WSL2, before the split (the code is unchanged):

| Run | Time | Notes |
|---|---|---|
| RC4 | about 1 us per byte |  |
| RC4, 1 MB of keystream | 1.0 s, 100 MB peak |  |

Messages have no length limit beyond memory: every loop over blocks or bytes is a tail call.

## Side channels

RC4's state is read and written at secret indices (a table walked by the bits of a secret index). None of this is constant-time, and Bend's runtime promises nothing about running time anyway. Do not use this package where timing attacks matter.

## Dependencies

`DEPS`: `bytes` (`Octets`), and its laws in the proofs; `cipher-core` (the error type `LcError`, the word helpers and tables the cipher is built from, and its laws in the proofs: XOR undone and the rest).

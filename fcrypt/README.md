# bend-osdev-fcrypt

FCrypt (the AFS specification, 2000), the 64-bit block cipher of AFS's rxkad, with a 64-bit key (56 bits used), on cipher-core's `LcBlock64`, with cipher-core's ECB and CBC (`modes64.bend`) over it. Its rounds are cipher-core's Feistel rounds over its round function.

The directory is `fcrypt` and the entry file `fcrypt/fcrypt.bend`; the hub name is `bend-osdev-fcrypt`. It is one of the packages split from bend-osdev-legacy-ciphers@0.1.0.0, which they supersede (that version stays on the hub as it was): cipher-core (what the ciphers share, and the 64-bit modes) and one package per cipher.

FCrypt is here for compatibility (AFS's rxkad): its key is 56 bits and its block 64 bits. None of the code here is constant-time (see Side channels).

## Specifications

Written from the public specification only; no implementation's source was read.

* **FCrypt:** T. Anderson, *Specification of FCrypt: Encryption for AFS
  Remote Procedure Calls* (openafs-devel mailing list, December 2000): the
  round function, the S-boxes S0 to S3 (transcribed into `gen/tables.py`),
  the key schedule (the 56-bit value rotated by 11), and PCBC (crypto's
  CrPcbc over this cipher). Test vectors: the two in the specification.

The test vectors were checked against the model in `ref/model.py` before they became laws or `check.bend` lines.

## Files

| File | Holds |
|---|---|
| `fcrypt.bend` | FCrypt |
| `gen/vectors.py` | the generator of the vector laws in `LAWS.bend`, their proofs in `PROOF.bend`, and `check.bend`'s `main` and expected `#|` lines, from `ref/model.py`; `python3 gen/vectors.py` rewrites them, `--check` checks they are up to date |
| `gen/tables.py` | the generator of `fcrypt.bend`'s table region (S0 to S3, transcribed from the specification); the same two modes |
| `ref/` | the differential test (`run.sh`, `gen.py`, `model.py`) |

The generated regions lie between `# BEGIN GENERATED by gen/<script>.py: <name>` and `# END GENERATED: <name>` lines; everything outside them is written by hand. After changing the vector laws, run `gen/vectors.py`.

## Public interface

The key type is opaque: built by the cipher's `key` functions from the raw key, used only through the cipher's defs. Every fallible function answers `Result<&2, &2, LcError, A>` with cipher-core's `LcError`: `LcBadKeyLength{got}` for a key of a length the cipher does not take (8 bytes); the 64-bit modes add `LcBadIvLength` and `LcNotBlockMultiple`.

**`fcrypt.bend`**

| Def / type | Meaning |
|---|---|
| `LcFcryptKey`, `LcFcrypt.key(o)` | an 8-byte key (the parity bits are ignored); opaque |
| `LcFcrypt.encrypt(k, b)`, `LcFcrypt.decrypt(k, b)` | one `LcBlock64` |

Everything else (`fc.*`, `LcFc*` other than the key type) is internal.

## With the 64-bit modes

cipher-modes' modes are written for 128-bit blocks, so a 64-bit cipher uses
cipher-core's `modes64.bend` instead: ECB and CBC on `LcBlock64`, the cipher
as template arguments:

```
import ../cipher-core/modes64.bend as X
import ../fcrypt/fcrypt.bend as C

X.Lc64.cbc_encrypt(~C.LcFcryptKey, ~C.LcFcrypt.encrypt, k, iv, m)
X.Lc64.cbc_decrypt(~C.LcFcryptKey, ~C.LcFcrypt.decrypt, k, iv, c)
```

For padding, cipher-modes' `Pkcs7.pad(8n, m)` and `Pkcs7.unpad(8n, m)` take
an 8-byte block size. crypto's ECB, CBC, CTR, PCBC and CBC-CS3 run over the
cipher too (crypto proves the ECB, CBC and PCBC round trips over it).

## Extension points

* **Any mode over the cipher:** it is `modes64.bend`'s template arguments (cipher-core), and crypto's; a new mode takes `~K`, `~enc`, `~dec` and never looks inside the key.
* **Replaceable internals:** the key type is opaque, so the cipher's representation (its round keys, its tables) can change without touching a caller. The cipher is a list of invertible steps, decryption the steps undone in reverse order; a faster implementation (bit-sliced S-boxes, combined tables, hardware instructions) can go behind the same defs, tied to these by the vectors and the differential test.

## Laws

`LAWS.bend` (4 laws).

**For every input:**

* `fcrypt_round_trip`, `fcrypt_round_trip_dual`: for every FCrypt key (every key size) and every 64-bit block, decryption undoes encryption and encryption undoes decryption.

**Vectors** (proved by computation): the specification's second vector (`fcrypt_spec`) and the refusal of a 7-byte key. The specification's first vector runs in `check.bend`.

How the round trips are proved: the cipher is a list of steps, each undone by its inverse whatever its round function or key is, so no proof evaluates the cipher. Here the rounds are cipher-core's Feistel rounds over FCrypt's F, undone whatever F is (cipher-core's `feistel_unrun_run`, `feistel_run_unrun`).

The proofs need nothing from another package beyond its public interface and laws: cipher-core's laws (above).

## Tests

* `check.bend` runs the specification's two vectors both ways (encryption, then decryption back), and the cipher through cipher-core's CBC (`modes64.bend`) over 16 KB both ways.
* `ref/run.sh` compares FCrypt against `ref/model.py` alone (neither `cryptography` nor `openssl` has it), on random keys, blocks and messages, each a block both ways and a CBC message both ways. **`ref/model.py` was written here from the specification, by the same author as this package**, and is first checked against the specification's published vectors. `run.sh` exits 77 when `python3` is missing.

## Speed

Measured on Bend 2.0.37, native builds (`bend file.bend -o prog`), WSL2, before the split (the code is unchanged):

| Run | Time | Notes |
|---|---|---|
| FCrypt, CBC through modes64.bend, 256 KB both ways | 1.4 s, 58 MB peak |  |

The cipher builds its lookup tables when its key is made and keeps them in the key (Bend 2.0.37 recomputes a table def at every call). Messages have no length limit beyond memory: every loop over blocks or bytes is a tail call.

## Side channels

The S-boxes are table lookups (trees walked by the bits of a secret index). None of this is constant-time, and Bend's runtime promises nothing about running time anyway. Do not use this package where timing attacks matter.

## Dependencies

`DEPS`: `bytes` (`Octets`); `word64` (the bit slicing the bit-level steps are built from); `cipher-core` (the error type `LcError`, the word helpers and tables the cipher is built from, and its laws in the proofs: XOR undone and the rest).

# bend-osdev-nlattr

Netlink attributes: the type-length-value records that netlink messages
carry (rtnetlink, generic netlink, nftables, ...), built, parsed and
validated against a policy. The counterpart of the kernel's `lib/nlattr.c`
interface (`nla_put`, `nla_parse`, `nla_validate`, `nla_find`, the
`nla_get_*` readers), written from RFC 3549 (the attribute format) and the kernel's netlink
documentation (its userspace-API netlink pages: attribute layout, flags,
policies and strict validation); no kernel source was read.

## What it implements

* **The attribute format.** A 4-byte header, two 16-bit fields in the
  header's byte order: `nla_len` (header and payload, without padding) and
  `nla_type`, whose top two bits are the flags `NLA_F_NESTED` (bit 15) and
  `NLA_F_NET_BYTEORDER` (bit 14) and whose low 14 bits are the type. Each
  attribute is padded with zero bytes to a multiple of 4.
* **Attributes** are `NlAttr{kind, nested, netorder, payload}`: the type, the
  two flags and the payload as `Octets`. A nested attribute's payload is
  itself a run of attributes, built with `nla.build` and parsed with
  `nla.parse`.
* **Building** (`nla.build`, `nla.put`): the attributes one after another,
  each padded with zeros. `NlBadType` for a type past 14 bits, `NlTooLong`
  for a length that does not fit `nla_len`.
* **Parsing** (`nla.parse`): `NlBadLength` for an `nla_len` below 4 or past
  the end of the buffer; with `strict`, `NlTrailing` for bytes left after
  the last attribute that are too few for a header (without it they are
  ignored, as the kernel's liberal parse does). The last attribute's padding
  may be missing, as the kernel accepts.
* **Policies** (`policy.bend`): a rule per type, `NlRule`: `NlUnspec{min}`
  (at least `min` bytes), `NlU8`, `NlU16`, `NlU32`, `NlU64` (integers; exact
  size or at least it), `NlString{max}` (at most `max` bytes, a final NUL not
  counted; 0 is no limit), `NlNulString{max}` (must end in NUL), `NlFlag`
  (no payload), `NlBinary{min, max}`, `NlNested{policy}` (the payload is
  attributes, validated against another policy of the set), `NlReject`.
  A policy set is a list; a nested rule names its policy by index, so
  policies refer to each other and to themselves without a recursive type.
  `NlCheck{parse, exact, unknown, nested_flag, depth}` says how to validate:
  `nla.check_strict(o)` is the kernel's `NL_VALIDATE_STRICT` (exact integer
  sizes, unknown types refused, nested attributes must carry
  `NLA_F_NESTED`, trailing bytes refused), `nla.check_liberal(o)` the old
  liberal checks; both allow 10 levels of nesting. Errors: `NlUnknown`,
  `NlTooShort`, `NlTooLarge`, `NlNoNul`, `NlNotFlag`, `NlNoNestedFlag`,
  `NlTooDeep`, each with the attribute's type.
* **Reading**: `nla.find` (the first attribute of a type), `nla.get_u8`,
  `get_u16`, `get_u32`, `get_u64` (in network order when the attribute has
  `NLA_F_NET_BYTEORDER`, else in the header's order).

## Extension points

* **Byte order** of the header is a parameter (`NlOrder`), little-endian by
  default (the host order of the machines tested); a big-endian host passes
  `NlBig`.
* **Strictness** is a parameter twice: trailing bytes when parsing
  (`NlOpts.strict`), and each of the kernel's strict checks separately
  (`NlCheck`'s fields), so a caller can mix them as old and new kernel
  interfaces do.
* **Policies** are data: a new attribute family is a new `NlPolicy` list; a
  new kind of rule is a new `NlRule` constructor and a case of
  `nla.step.kind`.
* **Validation fuel**: `nla.validate` takes a step bound; `parse_policy`
  gives it twice the buffer's length plus 2, more than enough: headers at
  every level are disjoint 4-byte runs, so there are at most `len / 4`
  attributes in all, and a step per attribute and per nested payload.

## Laws

`LAWS.bend`, for **every** byte order, list of attributes and buffer:

* `parse_build`: when `nla.build(o, as)` answers `Done{b}`, parsing `b`
  (strict or liberal, the same order) answers `Done{as}`;
* `pad_zero`: a built attribute's bytes after `nla_len` are zeros, exactly
  `nla.pad(nla_len)` of them; `put_len`: a built attribute is
  `nla.align(nla_len)` bytes long, a multiple of 4;
* `parse_within`: when `nla.parse(p, buf)` answers `Done{as}`, the
  attributes' headers and payloads fit in `buf`
  (`nla.span(as) <= Octets.len(buf)`); the parse never reads past the
  buffer;
* `parse_policy_parse`: when a parse with a policy succeeds, the plain parse
  answers the same attributes; `parse_policy_within`: so they fit in the
  buffer too;
* **vectors:** a `u32`, a string, both flags in network order, a parse of two
  attributes, and the parse errors `NlBadLength` and `NlTrailing`.

**What the proofs rely on.** Beyond bytes' interface laws (`octets_of_to`,
`octets_to_of`, `octets_append_list`, `octets_len_list`,
`octets_zeros_list`, `octets_drop_append`, `octets_of_list_idempotent`), the
proofs compute through bytes' public `byte` and `mask`: `proof_byte.bend`
shows that `byte` keeps each value below 256 by computing it for each of the
256 values (generated, as acpi's byte lemmas are). If bytes changed how it
computes `byte`, `gen/gen_byte.py`'s output would need checking again.

`LAWS_validate.bend` (24 laws, proved in `PROOF_validate.bend`, checked in
a process of its own; it imports bytes' proofs only). **Validation**, for
every check `NlCheck{p, exact, unknown, nf, depth}`, policy set, policy
index `pol` whose rules are `rs`, attribute `NlAttr{t, nd, nb, pl}` and
fuel of 2 steps or more: `nla.validate` of that attribute alone answers
exactly what its rule `List.get(rs, t)` describes, written in the law file
as a plain `Result` over the payload's length `l` and its last byte:

* `validate_no_rule`: no rule: `NlUnknown{t}` when the check refuses
  unknown types, else accepted;
* `validate_unspec`: `NlUnspec{min}`: `NlTooShort{t}` unless `min <= l`;
* `validate_u8`, `validate_u16`, `validate_u32`, `validate_u64`: with
  `exact`, `NlTooShort{t}` below the size and `NlTooLarge{t}` above it;
  without it, `NlTooShort{t}` below the size only;
* `validate_string`: `NlString{max}`: `NlTooLarge{t}` when `max` is not 0
  and the length without a final NUL is above `max`;
* `validate_nul_string`: `NlNulString{max}`: `NlNoNul{t}` unless the last
  byte is a NUL, then `NlTooLarge{t}` when `max` is not 0 and `l - 1` is
  above it;
* `validate_flag`: `NlFlag`: `NlNotFlag{t}` unless `l` is 0;
* `validate_binary`: `NlBinary{min, max}`: `NlTooShort{t}` unless
  `min <= l`, then `NlTooLarge{t}` when `max` is not 0 and `l` is above it;
* `validate_reject`: `NlReject`: `NlUnknown{t}`;
* `NlNested{sub}`: `validate_nested_no_flag`: `NlNoNestedFlag{t}` when the
  check asks for `NLA_F_NESTED` and the attribute lacks it;
  `validate_nested_too_deep`: `NlTooDeep` at depth 0;
  `validate_nested_bad`: the payload's parse error;
  `validate_nested_valid`: accepted with fuel `2 + f` when the payload
  parses to attributes that `nla.validate` accepts against policy `sub`,
  one level deeper, with fuel `f`. The proof (`nlv.L`) shows that work
  validated within `f` steps is still accepted with one more step and the
  attribute's empty remainder queued after it, and that the steps do not
  read the check's depth field.

**The readers**, for every byte order, type and value:
`get_u8_round_trip` (`nla.get_u8(nla.u8(t, v))` is `Some{byte(v)}`),
`get_u16_round_trip` (`Some{low16(v)}`), `get_u32_round_trip`,
`get_u64_round_trip`, `get_u32_be_round_trip` (a network-order value reads
back in either host order); `find_head`, `find_skip`, `find_nil`:
`nla.find` answers the first attribute of the type. **Witness:**
`validate_nested_example`, a nested attribute of one `u32` accepted
against a set of two policies, so the nested laws' hypotheses can hold.

The proofs use bytes' interface laws (`octets_at_list`, `octets_to_of`
and the field round trips) and compute `byte` on a word split into its
bits; they do not need `proof_byte.bend`, `proof_list.bend` or
`proof_nat.bend`.

**Not stated as laws** (tested only): that a nested payload's validation
failure is the attribute's (with fuel that runs out exactly at that point
the answers can differ: the payload's own validation runs out of steps,
while the attribute's, with one step more, may reach a later error; with
the fuel `nla.parse_policy` gives this cannot happen, but the law would
need a bound on the steps validation takes); validating a list of several
attributes (the laws take one attribute at a time; `ref/run.sh` checks
lists); `NlBadType` is not a vector because a type past 14 bits is a number
too large for the checker to expand (`check.bend` shows it).

## Tests

* `check.bend`: a buffer of a string, a `u32`, a flag, a nested attribute
  and a network-order value, built and parsed back; finding and reading a
  `u32` (present and absent); validation, strict and liberal, passing and
  failing; trailing bytes strict and liberal; each parse error; `NlBadType`;
  a big-endian build.
* `ref/run.sh` compares 202 cases with two references:
  * **the running kernel**: an `RTM_GETLINK` dump over a `NETLINK_ROUTE`
    socket (no privileges needed) gives the attributes the kernel built for
    each network interface; the package parses each, and its `IFLA_IFNAME`
    and `IFLA_MTU` must be what iproute2's `ip -j link show` reports, and
    its attribute list what the model parses (2 interfaces here);
  * **a model** in `ref/gen.py`, written from the RFC and the documentation:
    60 random attribute lists (with nesting) built and parsed back, each in a
    random order, 60
    damaged buffers (cut short, a corrupted length, bytes added) parsed
    strict and liberal, and 80 validations against random policy sets with
    nesting.
  It exits 77 (skipped) without `python3` or `ip`.

## Limitations

* Messages (`nlmsghdr`) and sockets are not here: this is the attribute
  layer only.
* The kernel's newer policy kinds (ranges, bitfields, masks, validation
  callbacks) are not modelled.
* Building, parsing and validating are linear in the bytes, through lists.

## Dependencies

`bend-osdev-bytes` (buffers are `Octets`) and `bend-osdev-word64`
(`nla.u64` and `nla.get_u64` use `W64`).

bend-osdev-u32, in the proofs only: its laws of `Nat` arithmetic and words'
values (`LAWS.bend`) and the order of `Nat` and words (`LAWS_order.bend`).

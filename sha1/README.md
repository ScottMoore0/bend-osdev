# bend-osdev-sha1

SHA-1 (FIPS 180-4), streaming (init, update, final) and one-shot, through
md-engine's Merkle–Damgård engine. **SHA-1 is broken for collisions**
(SHAttered, 2017): it is here for HMAC-SHA-1, PBKDF2-HMAC-SHA-1 and the
formats that require it.

The directory is `sha1` and the entry file `sha1/sha1.bend`; the hub name is
`bend-osdev-sha1`. It is one of the packages split from
bend-osdev-hashes@0.1.0.0, which they supersede (that version stays on the
hub as it was): md-engine (the Merkle–Damgård engine and what the hashes
share) and one package per hash.

## Specifications

Written from the public specification only; no GPL source was read.

* **SHA-1:** FIPS 180-4, *Secure Hash Standard (SHS)* (NIST, August 2015),
  sections 4.1.1, 4.2.1, 5.1.1, 5.3.1 and 6.1; NIST's SHA-1 example values
  ("abc" and the 448-bit message), and FIPS 180-2's third example (a
  million bytes "a").

## Files

| File | Holds |
|---|---|
| `sha1.bend` | SHA-1: `HsSha1.*` |
| `gen/spec.py` | the specification's tables (the initial value and the four constants K (FIPS 180-4, sections 4.2.1 and 5.3.1)), with their sources |
| `gen/rounds.py` | writes the unrolled compression function (the region "sha1" of `sha1.bend`) from `spec.py` |
| `gen/laws.py` | writes `LAWS.bend` and `PROOF.bend` |
| `gen/check.py` | writes `check.bend` and its expected output |
| `ref/model.py`, `ref/gen.py`, `ref/run.sh` | the differential test (Tests below) |

`python3 gen/<script>.py` rewrites what a generator writes, and `--check`
checks it is up to date. The generated region lies between `# BEGIN
GENERATED by gen/rounds.py: sha1` and `# END GENERATED: sha1`; everything
else in `sha1.bend` is written by hand.

Bend imports do not re-export: import md-engine's `md-engine.bend` beside
`sha1.bend` to name the state and chaining-value types.

## Public interface

| Def | Meaning |
|---|---|
| `HsSha1.init()` | the state before any byte (md-engine's `HsMdState<HsW5>`) |
| `HsSha1.update(s, o)` | the state after more bytes (`Octets`), in any pieces |
| `HsSha1.final(s)` | the digest of the bytes so far (20 bytes) |
| `HsSha1.digest(o)` | the digest in one call (`final(update(init(), o))`) |
| `HsSha1.compress(cv, block)` | the compression function on one 64-byte block (a list of bytes) |
| `HsSha1.iv()` | the initial chaining value |

Everything else (`hs.sha1.*`) is internal. The hash, as crypto's hash
interface takes it:

```
~Hs.HsMdState<Hs.HsW5>, ~64n, ~20n, ~HsSha1.init(), ~HsSha1.update, ~HsSha1.final, ~HsSha1.digest
```

## Extension points

* **The compression function is replaceable.** `HsSha1.compress` is one def
  written from the tables in `gen/spec.py`; a faster one (a different
  unrolling) can replace it, and the laws hold for every compression
  function (md-engine's `md_streaming`).
* **Any user of a hash:** the defs above are the template arguments
  crypto's hash interface takes, so HMAC, HKDF and PBKDF2 (crypto) run over
  SHA-1 with no adapter.
* **The engine and its types** are md-engine's (its README, Extension
  points).

## Laws

`LAWS.bend` (written by `gen/laws.py`) has 7 laws.

**For every input**, with no hypothesis:

* `sha1_streaming`: update over `a ++ b` is update over `a`, then `b`, from
  every state (md-engine's `md_streaming` at SHA-1's defs);
* `sha1_split` and `sha1_split3`: the streaming digest of any split into
  two or three pieces is the one-shot digest;
* `sha1_length`: the final digest of every state has 20 bytes
  (md-engine's `w5_be_length` at the chaining value after the padding), and
  `sha1_digest_length`: so has the one-shot digest of every message.

**Vectors**, by computation: FIPS 180-4's two SHA-1 examples (NIST's example
values: "abc" and the 448-bit message), `sha1_fips_1` and `_2`.

**Not laws, and why.** The digest's agreement with the algorithm's
definition for every message: a hash has no specification beyond its
algorithm, so the vectors and the differential test hold it.

The proofs need nothing from another package beyond its public interface and
laws: md-engine's `md_streaming` and `w5_be_length`.

## Tests

* `check.bend` (written by `gen/check.py`): the two examples through the
  public interface, the digest in one call and in three pieces through
  init/update/final, and a million bytes "a" (FIPS 180-2's third example).
  The expected lines are the specification's values.
* `ref/run.sh` (27 cases with the default seed): SHA-1 on 27 message lengths
  (around every block boundary up to three blocks, and 1000 and 4103 bytes),
  whole and cut into three pieces at random points, against Python's
  `hashlib` (OpenSSL). `ref/model.py` (written here, from the specification)
  is checked against the examples and against hashlib too.
* The crypto package's tests run SHA-1 through its hash interface, and HMAC
  and PBKDF2 over it, against Python's `hmac` and `hashlib.pbkdf2_hmac`
  (crypto/README.md).

## Sizes

Native builds (Bend 2.0.37, WSL2), a 1 MB pseudo-random message (its
building included), measured before the split (the code is unchanged): 0.12
s and 84 MB. Updates are tail calls over the bytes, so a message has no
length limit beyond memory.

## Notes on use

* **SHA-1 is broken for collisions.** Use SHA-256 or SHA-512 (crypto's
  `inst_sha2.bend`), SM3 or Streebog for new designs; HMAC-SHA-1 is still
  sound where existing protocols require it.
* None of this code is constant-time, and Bend's runtime promises nothing
  about running time.

## Dependencies

`DEPS`: `bytes` (`Octets`) and `md-engine` (the engine, the chaining-value
types and word helpers, and its laws in the proofs). No hub package.

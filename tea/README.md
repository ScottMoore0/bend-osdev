# bend-osdev-tea

TEA (Wheeler and Needham, 1994), a 64-bit block cipher with a 128-bit key, on cipher-core's `LcBlock64`, with cipher-core's ECB and CBC (`modes64.bend`) over it. It also holds the steps TEA and XTEA (the xtea package) share.

The directory is `tea` and the entry file `tea/tea.bend`; the hub name is `bend-osdev-tea`. It is one of the packages split from bend-osdev-legacy-ciphers@0.1.0.0, which they supersede (that version stays on the hub as it was): cipher-core (what the ciphers share, and the 64-bit modes) and one package per cipher.

TEA is here for compatibility: it has equivalent keys and related-key weaknesses, and its 64-bit block a birthday bound at 2^32 blocks. None of the code here is constant-time (see Side channels).

## Specifications

Written from the public specification only; no implementation's source was read.

* **TEA:** D. Wheeler, R. Needham, *TEA, a Tiny Encryption Algorithm*, Fast
  Software Encryption (1994). The paper gives no test vectors and no byte
  order for the words: the order is a parameter (little-endian words by
  default, as the Linux kernel's tea takes them; big-endian with `key_be`),
  and so is the number of cycles (32 by default).

The paper publishes no test values: `check.bend`'s lines are the model's (`ref/model.py`), and the model is checked against itself (decryption against encryption) and against this package.

## Files

| File | Holds |
|---|---|
| `tea.bend` | TEA, and the steps TEA and XTEA share |
| `gen/vectors.py` | the generator of the vector laws in `LAWS.bend`, their proofs in `PROOF.bend`, and `check.bend`'s `main` and expected `#|` lines, from `ref/model.py`; `python3 gen/vectors.py` rewrites them, `--check` checks they are up to date |
| `gen/proof.py` | the generator of `PROOF.bend`'s region "adc" (a subtraction undoes an addition, and an addition a subtraction, for every word, by induction on the bits with the carry and the borrow); the same two modes |
| `ref/` | the differential test (`run.sh`, `gen.py`, `model.py`) |

The generated regions lie between `# BEGIN GENERATED by gen/<script>.py: <name>` and `# END GENERATED: <name>` lines; everything outside them is written by hand. After changing the vector laws, run `gen/vectors.py`.

## Public interface

The key type is opaque: built by the cipher's `key` functions from the raw key, used only through the cipher's defs. Every fallible function answers `Result<&2, &2, LcError, A>` with cipher-core's `LcError`: `LcBadKeyLength{got}` for a key of a length the cipher does not take (16 bytes); the 64-bit modes add `LcBadIvLength` and `LcNotBlockMultiple`.

**`tea.bend`**

| Def / type | Meaning |
|---|---|
| `LcTeaKey`, `LcTea.key(o)`, `LcTea.key_be(o)` | 16 bytes, words little-endian (the named default) or big-endian, 32 cycles; opaque |
| `LcTea.key_with(le, n, o)` | the byte order and the number of cycles as parameters |
| `LcTea.encrypt(k, b)`, `LcTea.decrypt(k, b)` | one `LcBlock64` |

**The steps TEA and XTEA share** (the xtea package builds on these; they are
public so that it can):

| Def / type | Meaning |
|---|---|
| `LcTeaOp` (open): `LcTeaY{s, a, b}`, `LcTeaZ{s, a, b}`, `LcXteaY{c}`, `LcXteaZ{c}`, `LcTeaBswap{}` | a step: TEA's or XTEA's function of one half added to the other, or both words byte-swapped |
| `tea.run(os, b)`, `tea.unrun(os, b)` | a list of steps, and the list undone last to first |
| `tea.order(le, os)` | the steps in a byte order (little-endian words are byte-swapped on the way in and out) |
| `tea.word(le, xs, i)` | key word i of the key bytes xs, in a byte order |
| `tea.delta()` | the constant 0x9E3779B9 |

Everything else (`tea.*` other than those, `xtea.g`) is internal.

## With the 64-bit modes

the 128-bit modes are written for 128-bit blocks, so a 64-bit cipher uses
cipher-core's `modes64.bend` instead: ECB and CBC on `LcBlock64`, the cipher
as template arguments:

```
import ../cipher-core/modes64.bend as X
import ../tea/tea.bend as C

X.Lc64.cbc_encrypt(~C.LcTeaKey, ~C.LcTea.encrypt, k, iv, m)
X.Lc64.cbc_decrypt(~C.LcTeaKey, ~C.LcTea.decrypt, k, iv, c)
```

For padding, pkcs7's `Pkcs7.pad(8n, m)` and `Pkcs7.unpad(8n, m)` take
an 8-byte block size. crypto's ECB, CBC, CTR, PCBC and CBC-CS3 run over the
cipher too (crypto proves the ECB, CBC and PCBC round trips over it).

## Extension points

* **Any mode over the cipher:** it is `modes64.bend`'s template arguments (cipher-core), and crypto's; a new mode takes `~K`, `~enc`, `~dec` and never looks inside the key.
* **Key sizes and options are parameters** where the specification gives a choice: the words' byte order and the number of cycles are parameters (`key_with`), the paper leaving them open.
* **Replaceable internals:** the key type is opaque, so the cipher's representation (its round keys, its tables) can change without touching a caller. The cipher is a list of invertible steps, decryption the steps undone in reverse order; a faster implementation (bit-sliced S-boxes, combined tables, hardware instructions) can go behind the same defs, tied to these by the vectors and the differential test.
* **XTEA** reuses the steps listed above (the xtea package): a cipher built from these steps gets its round trip from `tea_steps_round_trip`.

## Laws

`LAWS.bend` (5 laws).

**For every input:**

* `tea_round_trip`, `tea_round_trip_dual`: for every TEA key (every key size, byte order and number of cycles) and every 64-bit block, decryption undoes encryption and encryption undoes decryption;
* `tea_steps_round_trip`, `tea_steps_round_trip_dual`: any list of the steps TEA and XTEA share, run and then undone last to first, gives the block back, and the other way round (stated simple side first, for XTEA's proofs).

**Vectors** (proved by computation): the refusal of a 15-byte key. No specification publishes TEA's values: `check.bend` runs the model's, and the differential test compares with the model.

How the round trips are proved: the cipher is a list of steps, each undone by its inverse whatever its round function or key is, so no proof evaluates the cipher. Here each step adds a function of one half to the other, undone by subtracting it (`(a + b) - b == a` for every word, by induction on the bits with the carry, `gen/proof.py`); the byte swaps are undone by themselves (cipher-core's `bswap_bswap`).

The proofs need nothing from another package beyond its public interface and laws: cipher-core's laws (above).

## Tests

* `check.bend` runs TEA in both byte orders (the model's values: the paper publishes none) both ways (encryption, then decryption back), and the cipher through cipher-core's CBC (`modes64.bend`) over 16 KB both ways.
* `ref/run.sh` compares TEA against `ref/model.py` alone (neither `cryptography` nor `openssl` has it), on random keys, blocks and messages, each a block both ways and a CBC message both ways. **`ref/model.py` was written here from the specification, by the same author as this package**, and is first checked against the specification's published vectors (the paper has none: the model is checked against itself, decryption against encryption). `run.sh` exits 77 when `python3` is missing.

Messages have no length limit beyond memory: every loop over blocks or bytes is a tail call.

## Side channels

TEA's steps are additions, shifts and XORs on words, but the words are Bend values whose operations promise no timing. None of this is constant-time, and Bend's runtime promises nothing about running time anyway. Do not use this package where timing attacks matter.

## Dependencies

`DEPS`: `bytes` (`Octets`); `cipher-core` (the error type `LcError`, the word helpers and tables the cipher is built from, and its laws in the proofs: XOR undone and the rest).

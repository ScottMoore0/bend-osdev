# bend-osdev-md4

MD4 (RFC 1320), streaming (init, update, final) and one-shot, through
md-engine's Merkle–Damgård engine. **MD4 is broken** (collisions are found
by hand): it is here to read what already uses it (NTLM, rsync's older
protocols).

The directory is `md4` and the entry file `md4/md4.bend`; the hub name is
`bend-osdev-md4`. It is one of the packages split from
bend-osdev-hashes@0.1.0.0, which they supersede (that version stays on the
hub as it was): md-engine (the Merkle–Damgård engine and what the hashes
share) and one package per hash.

## Specifications

Written from the public specification only; no GPL source was read.

* **MD4:** RFC 1320, R. Rivest, *The MD4 Message-Digest Algorithm* (April
  1992), section 3 (the algorithm) and appendix A.5 (the test suite).

## Files

| File | Holds |
|---|---|
| `md4.bend` | MD4: `HsMd4.*` |
| `gen/spec.py` | the specification's tables (the three rounds' shifts, word orders and constants (RFC 1320, section 3.4)), with their sources |
| `gen/rounds.py` | writes the unrolled compression function (the region "md4" of `md4.bend`) from `spec.py` |
| `gen/laws.py` | writes `LAWS.bend` and `PROOF.bend` |
| `gen/check.py` | writes `check.bend` and its expected output |
| `ref/model.py`, `ref/gen.py`, `ref/run.sh` | the differential test (Tests below) |

`python3 gen/<script>.py` rewrites what a generator writes, and `--check`
checks it is up to date. The generated region lies between `# BEGIN
GENERATED by gen/rounds.py: md4` and `# END GENERATED: md4`; everything
else in `md4.bend` is written by hand.

Bend imports do not re-export: import md-engine's `md-engine.bend` beside
`md4.bend` to name the state and chaining-value types.

## Public interface

| Def | Meaning |
|---|---|
| `HsMd4.init()` | the state before any byte (md-engine's `HsMdState<HsW4>`) |
| `HsMd4.update(s, o)` | the state after more bytes (`Octets`), in any pieces |
| `HsMd4.final(s)` | the digest of the bytes so far (16 bytes) |
| `HsMd4.digest(o)` | the digest in one call (`final(update(init(), o))`) |
| `HsMd4.compress(cv, block)` | the compression function on one 64-byte block (a list of bytes) |
| `HsMd4.iv()` | the initial chaining value |

Everything else (`hs.md4.*`) is internal. The hash, as crypto's hash
interface takes it:

```
~Hs.HsMdState<Hs.HsW4>, ~64n, ~16n, ~HsMd4.init(), ~HsMd4.update, ~HsMd4.final, ~HsMd4.digest
```

## Extension points

* **The compression function is replaceable.** `HsMd4.compress` is one def
  written from the tables in `gen/spec.py`; a faster one (a different
  unrolling) can replace it, and the laws hold for every compression
  function (md-engine's `md_streaming`).
* **Any user of a hash:** the defs above are the template arguments
  crypto's hash interface takes, so HMAC, HKDF and PBKDF2 (crypto) run over
  MD4 with no adapter.
* **The engine and its types** are md-engine's (its README, Extension
  points).

## Laws

`LAWS.bend` (written by `gen/laws.py`) has 12 laws.

**For every input**, with no hypothesis:

* `md4_streaming`: update over `a ++ b` is update over `a`, then `b`, from
  every state (md-engine's `md_streaming` at MD4's defs);
* `md4_split` and `md4_split3`: the streaming digest of any split into
  two or three pieces is the one-shot digest;
* `md4_length`: the final digest of every state has 16 bytes
  (md-engine's `w4_le_length` at the chaining value after the padding), and
  `md4_digest_length`: so has the one-shot digest of every message.

**Vectors**, by computation: all seven of RFC 1320's test suite (appendix
A.5), `md4_rfc1320_1` to `_7`.

**Not laws, and why.** The digest's agreement with the algorithm's
definition for every message: a hash has no specification beyond its
algorithm, so the vectors and the differential test hold it.

The proofs need nothing from another package beyond its public interface and
laws: md-engine's `md_streaming` and `w4_le_length`.

## Tests

* `check.bend` (written by `gen/check.py`): RFC 1320's seven test values
  through the public interface, the digest in one call and in three pieces
  through init/update/final. The expected lines are the specification's
  values.
* `ref/run.sh` (27 cases with the default seed): MD4 on 27 message lengths
  (around every block boundary up to three blocks, and 1000 and 4103 bytes),
  whole and cut into three pieces at random points, against `ref/model.py`,
  since Python's hashlib lacks MD4 here (OpenSSL 3 keeps it in its legacy
  provider). **The model shares an author with the package**: it is checked
  first against RFC 1320's test suite, but the differential test is against
  that model alone. Its tables are `gen/spec.py`'s, so a wrong table would
  show in the specification's vectors (which agree) rather than in the
  differential test.
* The crypto package's tests run MD4 through its hash interface, and HMAC
  over it, against Python's `hmac` (crypto/README.md).

## Sizes

Not measured on its own; MD5, of the same shape, takes 0.12 s and 84 MB
for a 1 MB message (native, Bend 2.0.37). Updates are tail calls over the
bytes, so a message has no length limit beyond memory.

## Notes on use

* **MD4 is broken for collisions.** Use SHA-256 or SHA-512 (crypto's
  `inst_sha2.bend`), SM3 or Streebog for new designs.
* None of this code is constant-time, and Bend's runtime promises nothing
  about running time.

## Dependencies

`DEPS`: `bytes` (`Octets`) and `md-engine` (the engine, the chaining-value
types and word helpers, and its laws in the proofs). No hub package.

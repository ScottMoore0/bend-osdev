# bend-osdev-md5

MD5 (RFC 1321), streaming (init, update, final) and one-shot, through
md-engine's Merkle–Damgård engine. **MD5 is broken for collisions**: use
it for checksums and the formats that require it, not for security.

The directory is `md5` and the entry file `md5/md5.bend`; the hub name is
`bend-osdev-md5`. It is one of the packages split from
bend-osdev-hashes@0.1.0.0, which they supersede (that version stays on the
hub as it was): md-engine (the Merkle–Damgård engine and what the hashes
share) and one package per hash.

## Specifications

Written from the public specification only; no GPL source was read.

* **MD5:** RFC 1321, R. Rivest, *The MD5 Message-Digest Algorithm* (April
  1992), section 3 and appendix A.5.

## Files

| File | Holds |
|---|---|
| `md5.bend` | MD5: `HsMd5.*` |
| `gen/spec.py` | the specification's tables (the table T[i] = floor(2^32 abs(sin i)), the shifts and the word order of each step (RFC 1321, section 3.4)), with their sources |
| `gen/rounds.py` | writes the unrolled compression function (the region "md5" of `md5.bend`) from `spec.py` |
| `gen/laws.py` | writes `LAWS.bend` and `PROOF.bend` |
| `gen/check.py` | writes `check.bend` and its expected output |
| `ref/model.py`, `ref/gen.py`, `ref/run.sh` | the differential test (Tests below) |

`python3 gen/<script>.py` rewrites what a generator writes, and `--check`
checks it is up to date. The generated region lies between `# BEGIN
GENERATED by gen/rounds.py: md5` and `# END GENERATED: md5`; everything
else in `md5.bend` is written by hand.

Bend imports do not re-export: import md-engine's `md-engine.bend` beside
`md5.bend` to name the state and chaining-value types.

## Public interface

| Def | Meaning |
|---|---|
| `HsMd5.init()` | the state before any byte (md-engine's `HsMdState<HsW4>`) |
| `HsMd5.update(s, o)` | the state after more bytes (`Octets`), in any pieces |
| `HsMd5.final(s)` | the digest of the bytes so far (16 bytes) |
| `HsMd5.digest(o)` | the digest in one call (`final(update(init(), o))`) |
| `HsMd5.compress(cv, block)` | the compression function on one 64-byte block (a list of bytes) |
| `HsMd5.iv()` | the initial chaining value |

Everything else (`hs.md5.*`) is internal. The hash, as crypto's hash
interface takes it:

```
~Hs.HsMdState<Hs.HsW4>, ~64n, ~16n, ~HsMd5.init(), ~HsMd5.update, ~HsMd5.final, ~HsMd5.digest
```

## Extension points

* **The compression function is replaceable.** `HsMd5.compress` is one def
  written from the tables in `gen/spec.py`; a faster one (a different
  unrolling) can replace it, and the laws hold for every compression
  function (md-engine's `md_streaming`).
* **Any user of a hash:** the defs above are the template arguments
  crypto's hash interface takes, so HMAC, HKDF and PBKDF2 (crypto) run over
  MD5 with no adapter.
* **The engine and its types** are md-engine's (its README, Extension
  points).

## Laws

`LAWS.bend` (written by `gen/laws.py`) has 12 laws.

**For every input**, with no hypothesis:

* `md5_streaming`: update over `a ++ b` is update over `a`, then `b`, from
  every state (md-engine's `md_streaming` at MD5's defs);
* `md5_split` and `md5_split3`: the streaming digest of any split into
  two or three pieces is the one-shot digest;
* `md5_length`: the final digest of every state has 16 bytes
  (md-engine's `w4_le_length` at the chaining value after the padding), and
  `md5_digest_length`: so has the one-shot digest of every message.

**Vectors**, by computation: all seven of RFC 1321's test suite (appendix
A.5), `md5_rfc1321_1` to `_7`.

**Not laws, and why.** The digest's agreement with the algorithm's
definition for every message: a hash has no specification beyond its
algorithm, so the vectors and the differential test hold it.

The proofs need nothing from another package beyond its public interface and
laws: md-engine's `md_streaming` and `w4_le_length`.

## Tests

* `check.bend` (written by `gen/check.py`): RFC 1321's seven test values
  through the public interface, the digest in one call and in three pieces
  through init/update/final. The expected lines are the specification's
  values.
* `ref/run.sh` (27 cases with the default seed): MD5 on 27 message lengths
  (around every block boundary up to three blocks, and 1000 and 4103 bytes),
  whole and cut into three pieces at random points, against Python's
  `hashlib` (OpenSSL). `ref/model.py` (written here, from the specification)
  is checked against RFC 1321's test suite and against hashlib too; the
  laws' vectors were checked against it.
* The crypto package's tests run MD5 through its hash interface, and HMAC
  and PBKDF2 over it, against Python's `hmac` and `hashlib.pbkdf2_hmac`
  (crypto/README.md).

## Sizes

Native builds (Bend 2.0.37, WSL2), a 1 MB pseudo-random message (its
building included), measured before the split (the code is unchanged): 0.12
s and 84 MB. Updates are tail calls over the bytes, so a message has no
length limit beyond memory.

## Notes on use

* **MD5 is broken for collisions.** Use SHA-256 or SHA-512 (crypto's
  `inst_sha2.bend`), SM3 or Streebog for new designs.
* None of this code is constant-time, and Bend's runtime promises nothing
  about running time.

## Dependencies

`DEPS`: `bytes` (`Octets`) and `md-engine` (the engine, the chaining-value
types and word helpers, and its laws in the proofs). No hub package.

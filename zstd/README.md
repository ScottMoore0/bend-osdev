# bend-osdev-zstd

Zstandard decompression and compression. The decoder handles the whole
format of RFC 8878 (every block, literals and sequence mode, dictionaries,
skippable frames, content checksums), is safe against malformed input, and
can be fed its input in pieces. The compressor writes raw, RLE and
compressed blocks (a greedy LZ77 matcher), and what it writes decodes back to
its input, which is proved for every input.

## Specification

Written from these documents only:

* **RFC 8878**, "Zstandard Compression and the 'application/zstd' Media
  Type", Y. Collet and M. Kucherawy, February 2021: the frame format, blocks,
  literals, sequences, FSE and Huffman coding, dictionaries.
* **The xxHash specification** (`xxhash_spec.md`, "xxHash fast digest
  algorithm", from the xxHash project): XXH64, the content checksum, in
  `xxh64.bend` and again in `ref/zstdref.py`.
* **libzstd's public API documentation** (the `zstd.h` and `zdict.h`
  manual: function names, parameter names and numbers), used only to drive
  libzstd 1.5.5 from the reference test through `ctypes`, as a black box.

No implementation's source was read. Where RFC 8878 leaves a choice open,
the package makes the one below, some of them after experiments with
libzstd as a black box. `python3 ref/gen.py edges` repeats those
experiments: it prints, for each of the reference test's hand-built frames
(the edge cases), zstdref.py's answer, which is the package's, and
libzstd's.

### Choices the specification leaves open

* **Block size.** Every block, raw and RLE ones too, may regenerate at most
  Block_Maximum_Size (the smaller of 128 KB and the window size), as RFC 8878
  section 3.1.1.2.4 says. libzstd's one-shot decoder accepts larger raw and
  RLE blocks in single-segment frames; this package answers
  `ZstdBlockTooLarge`.
* **Offsets.** A match may reach at most the window size back (and, while
  the output is shorter than the window, into the dictionary's content), as
  section 5 says; further is `ZstdBadOffset`. libzstd's one-shot decoder is
  more lenient. A repeat offset that works out to 0 (Repeated_Offset1 − 1
  when it is 1) is `ZstdBadOffset`; the RFC calls it corruption, and libzstd
  accepts such frames.
* **Four literal streams** need at least 6 regenerated bytes (each stream
  holds a quarter, rounded up); fewer is `ZstdBadLiteralsHeader`, as libzstd
  answers too.
* **A sequences section of zero sequences** must be the single byte 0;
  anything after it is `ZstdBadSequencesHeader` (libzstd refuses it too).
* **The stream.** Empty input decodes to empty output (as libzstd's). After
  the last frame, 1 to 3 bytes are `ZstdTruncated`, and 4 or more that are
  no magic number `ZstdBadMagic`.
* **The frame header's unused bit** (bit 4 of the descriptor) is ignored, as
  the RFC says a decoder should; the reserved bit (bit 3) is
  `ZstdReservedBit`.
* **Windows** up to `max_window` are accepted; larger ones are
  `ZstdWindowTooLarge`. RFC 8878 recommends supporting at least 8 MB; the
  default is 128 MiB (2^27), the default limit libzstd's manual documents.
* **The output limit** is checked a block at a time, before the block's
  bytes are produced: a raw block's size when its header arrives, an RLE
  block's when its byte does, a compressed block's once it is decoded.
* **Dictionary IDs.** A frame naming a dictionary ID must match the
  dictionary's (a formatted dictionary's ID; raw content has ID 0, which
  matches only frames without one): otherwise `ZstdDictionaryMismatch`.

## API

Byte strings are `Octets` (bend-osdev-bytes), 64-bit values `W64`
(bend-osdev-word64). Everything that reads input answers
`Result<&2, &2, ZstdError, A>`.

### Decompression (`zstd.bend`)

| Def | Meaning |
|---|---|
| `decompress(src)` | the content of the stream `src` (frames back to back), with `ZstdOptions.default()` |
| `decompress_with(opts, src)` | the same, with these options |
| `ZstdOptions{limit, verify, dict, max_window}` | the most bytes to produce (`ZstdLimit{max}`, a `U32`, or `ZstdNoLimit{}`); whether to check content checksums; the dictionary every frame starts with (`Octets`: raw content, or a formatted dictionary; empty: none); the largest window accepted (`U32`) |
| `ZstdOptions.default()` | at most 64 MiB, checksums checked, no dictionary, windows up to 128 MiB |
| `ZstdOptions.unlimited()` | the same without a limit on the output, for trusted input |
| `Zstd.start(opts)` | a streaming decoder (`ZstdDecoder`) at the start of a stream |
| `Zstd.feed(d, o)` | the decoder after the bytes `o` |
| `Zstd.take(d)` | the output decoded so far and not yet taken, and the decoder without it (`ZstdPiece{dec, out}`) |
| `Zstd.finish(d)` | the end of the input: the output not yet taken, or the failure (a stream that stops inside a frame is `ZstdTruncated`) |

`ZstdLimit` and `ZstdDecoder` are in `frame.bend`; `ZstdDecoder` is opaque.
Output is answered a block at a time: a compressed block is decoded once all
its bytes have arrived, a raw or RLE block byte by byte.

### Compression (`compress.bend`)

| Def | Meaning |
|---|---|
| `compress(o)` | a frame holding `o`, with `ZstdCompressOptions.default()` |
| `compress_with(opts, o)` | the same, with these options; checked by decoding it (should it not give `o` back, the frame of `Zstd.raw_frame(o)` instead) |
| `compress_unchecked(opts, o)` | the same without the check |
| `ZstdCompressOptions{block_size, checksum, matcher}` | where the content is cut into blocks (`U32`, 1 to 131072; 0, or more than 131072, means 131072); whether to write the content checksum; whether to look for matches (else raw and RLE blocks only). Default: 131072, checksum, matcher |
| `Zstd.raw_frame(o)` | the simplest frame holding `o` (a 1 KB window, each byte a raw block), whose decoding is proved |

`compress` writes a single-segment frame with the content size, cut into
blocks; each block is RLE when all its bytes are equal, compressed when that
is smaller, otherwise raw. Compressed blocks hold raw literals and sequences
coded with the predefined tables; the matcher is greedy, with a
single-entry hash table (16384 slots, keyed by the next four bytes) carried
from block to block, matches of 4 bytes or more, and offsets reaching back
anywhere in the frame.

| `ZstdLit.decode`, `ZstdSeq.decode`, `ZstdBlk.decode` | `literals.bend`, `sequences.bend`, `block.bend` | the sections and blocks, for a caller with its own frame layer |

Type names: `ZstdError`, `ZstdOptions`, `ZstdLimit`, `ZstdPiece`,
`ZstdCompressOptions`, `ZstdFseProb`, `ZstdFseEntry`, `ZstdFseTable`,
`ZstdFseDesc`, `ZstdFseSyms`, `ZstdHufTable`, `ZstdHufRead`, `ZstdHufSyms`,
`ZstdBits`, `ZstdDict`, `ZstdLiterals`, `ZstdSequences`, `ZstdSeq`,
`ZstdSeqTables`, `ZstdXxh64` are open records; `ZstdDecoder`, `ZstdWindow`,

### Failures (`ZstdError`, `error.bend`)

| Constructor | When |
|---|---|
| `ZstdTruncated` | the input ends inside a frame (or 1 to 3 bytes follow the last frame) |
| `ZstdBadMagic` | neither a Zstandard nor a skippable frame starts where a frame should |
| `ZstdReservedBit` | the frame header descriptor's reserved bit is set |
| `ZstdWindowTooLarge` | the window passes `max_window` |
| `ZstdDictionaryMismatch` | the frame's dictionary ID is not the dictionary's |
| `ZstdBadBlockType` | block type 3 (reserved) |
| `ZstdBlockTooLarge` | a block passes Block_Maximum_Size, or regenerates more |
| `ZstdBadLiteralsHeader` | a literals section header that cannot be (sizes past the block, 4 streams of fewer than 6 bytes) |
| `ZstdBadHuffmanTree` | a malformed Huffman tree description |
| `ZstdNoHuffmanTree` | treeless literals with no earlier tree |
| `ZstdBadHuffmanStream` | a Huffman stream that does not decode to its size exactly, or a bad jump table |
| `ZstdBadFseTable` | a malformed FSE table description |
| `ZstdNoFseTable` | repeat mode with no earlier table |
| `ZstdBadSequencesHeader` | a malformed sequences section header (reserved bits, bytes after zero sequences) |
| `ZstdBadSequenceStream` | a sequence bitstream that is malformed or not used up exactly |
| `ZstdLiteralsExhausted` | sequences ask for more literals than the section holds |
| `ZstdBadOffset` | an offset of 0 or past the window (and dictionary) |
| `ZstdOutputTooLarge` | the output would pass the limit |
| `ZstdBadContentSize` | the content is not the size the frame header says |
| `ZstdBadChecksum` | the content checksum does not match (when checking) |
| `ZstdBadDictionary` | a malformed formatted dictionary |

`ZstdError.show(e)` names a failure.

## Dictionaries

Both kinds of RFC 8878 section 5 are supported in decoding: **raw content**
(any bytes not starting with the dictionary magic number), which frames use
as history before their first byte, and **formatted dictionaries** (magic
number, ID, Huffman and FSE tables, the three repeat offsets, content), whose
tables and repeat offsets a frame starts with, so its first block may use
treeless literals and repeat modes. The reference test decodes frames
libzstd writes with dictionaries `ZDICT_trainFromBuffer` trains and with
raw-content ones. The compressor does not take a dictionary yet.

## Extension points

* **Options:** `ZstdOptions` (decoding) and `ZstdCompressOptions`
  (compression) hold the real choices, with named defaults.
* **Streaming:** the decoder streams (`Zstd.start` / `feed` / `take` /
  `finish`); it holds the window (an `Array`, as large as the frame's window)
  and at most one compressed block of input. The compressor is one-shot: it
  writes single-segment frames, whose header records the content size, so
  the whole content must be known first. A streaming writer would write a
  window descriptor instead and keep its matcher's table and the window
  between pieces; `cmp.w.loop` (one block at a time, the table carried over)
  is its core already.
* **Better compression**, in order of value: Huffman-coded literals (the
  encoder is here already: `ZstdHuf.of_weights`, `ZstdHuf.encode`,
  `ZstdBits.pack_backward`; what is missing is building weights from
  frequencies and choosing per block), FSE-compressed sequence tables
  (`ZstdFse.encode` takes any table), repeat offsets, hash chains or lazy
  matching. `compress_with` checks its frame whatever the writer does, so a
  better writer needs no new proof, only the differential test.
* **The coders alone:** `fse.bend` and `huffman.bend` depend on nothing but
  `bits.bend`, with laws of their own, so other formats using FSE or
  Huffman coding (zstd's own dictionaries, others) can use them.
* **The window:** `block.bend`'s `ZstdWindow` answers the byte at an offset;
  the laws do not depend on how, so it can be replaced.

## Laws

`LAWS.bend` (a draft, not yet reviewed by the maintainer) has 52 laws.

**For every input** (properties, proved by induction):

* `output_within_max`: whatever the input, options and dictionary,
  `decompress_with` never answers more bytes than its limit;
* `stream_pieces`: feeding the decoder `a` then `b` is feeding it `a ++ b`,
  for every option;
* `one_shot_is_streaming`: without a limit, `decompress_with` is the
  streaming decoder fed its input in any two pieces;
* `bad_magic_refused`: four bytes that are neither magic number
  (`ZstdFrame.is_zstd`, `ZstdFrame.is_skippable`) are `ZstdBadMagic`, whatever
  follows them and whatever the limit and options (without a dictionary);
* `fse_round_trip`: for **every** FSE table and symbols, the bits
  `ZstdFse.encode` writes (whenever it writes any) decode back to the symbols,
  whatever follows them;
* `huf_round_trip`: the same for every Huffman code and `ZstdHuf.encode`;
* `bits_round_trip`: a field of `n` bits holding `v < 2^n` reads back as
  `v`, whatever follows;
* `raw_frame_round_trip`: `Zstd.raw_frame(o)` decodes back to `o`, for every
  `o`;
* `compress_round_trip`: `decompress(compress_with(opts, o)) == Done{o}` for
  every `o` and every option.

Every law with a hypothesis has a satisfiability witness (`witness_bits`,
`witness_fse`, `witness_huf`, `witness_bad_magic`).

The compressor's round trip holds for every input because `compress_with`
decodes its frame and compares, and answers `Zstd.raw_frame(o)` (whose round
trip is proved) should they differ. The proof covers the check and the
fallback; it does not show that the matcher and sequence encoder are right
on their own (that would follow the hash table and the FSE state machine
through the decoder bit by bit). The differential test covers them, and
checks that the fallback never happens on its inputs. The FSE and Huffman
laws are the parts of that which are proved: the coders the compressor uses
decode back what they encode, for every table.

**Vectors** (proved by computation):

* RFC 8878's examples: the Huffman example of section 4.2.1.1 (weights 4, 3,
  2, 0, 1 imply weight 1 for the last symbol; the codes 1, 01, 001, none,
  0000, 0001); the predefined distributions' first decoding-table states;
  XXH64 of the empty input and of "abc" (xxhash_spec.md's values);
* frames written byte by byte from RFC 8878's descriptions: the empty
  stream, a raw block, an RLE block with a checksum, a skippable frame, two
  frames, a compressed block (raw literals, predefined tables), Huffman
  literals with RLE tables and a checksum, a match into a raw-content
  dictionary; and one malformed frame for each failure the decoder names;
* compression: the frames `compress` writes for empty input, 40 equal bytes
  and `"bend-bend-bend-bend!"`, and `Zstd.raw_frame("ab")`.

The proofs follow the decoder byte by byte. Octets and W64 enter them only
through bytes' and word64's public defs and laws.

## Tests

`ref/zstdref.py` is an independent Zstandard decoder and encoder in Python,
written here from RFC 8878 (with XXH64 from xxhash_spec.md). **It shares an
author with this package**, so it checks the package against a second
reading of the RFC. libzstd (1.5.5 here, through `ctypes`) and the `zstd`
tool, when installed, are the independent checks.

`ref/run.sh` (seed 2026, about 40 seconds) checks the following; the inputs
include text from the repository's top-level documents, so the counts move a
little when those change:

* **decoding, 749 cases**, the package's answer (the content's length and
  XXH64, or the failure) against zstdref.py's and, for frames libzstd
  accepts, libzstd's:
  * 120 frames libzstd writes (levels −5 to 19, with and without checksums,
    with trained and raw-content dictionaries); frames of the `zstd` tool
    when it is installed (0 here: it is not);
  * 160 frames zstdref.py writes over every part of the format: raw, RLE and
    compressed blocks; raw, RLE, Huffman (1 and 4 streams, direct and
    FSE-compressed weights) and treeless literals; predefined, RLE,
    FSE-compressed and repeat sequence tables; window descriptors, content
    sizes, checksums, dictionary IDs, skippable and concatenated frames;
  * 31 hand-built frames (the edge cases above, every named failure);
  * 400 corruptions of these (bytes changed, deleted, inserted, cut off):
    the same bytes or the same failure as zstdref.py;
  * 38 output limits, one byte short of the content and exactly it;
* **compression, 100 cases** (block sizes, checksums on and off, the
  matcher on and off): every frame `compress_with` writes decodes back to its
  input with zstdref.py, with libzstd and with `zstd -d` (when installed),
  and the check never fell back (307230 bytes in, 206562 out).

`ref/run.sh` exits 77 (skip) only without `python3`; without libzstd or
the tool, the checks against zstdref.py still run. CI needs the apt package
**`zstd`** (the tool; it brings `libzstd1`) for the independent checks.

## Speed and sizes

Measured on Bend 2.0.37, native builds (`bend file.bend -o prog`), WSL2,
each run including reading the input file into a list and, for decoding,
hashing the output with XXH64. The input: 1 MiB of this repository's Bend
sources (text), and 1 MiB of pseudo-random bytes.

| Run, 1 MiB | Time | Peak RAM | Size |
|---|---|---|---|
| decode libzstd `-1` frame of the text | 1.05 s | 125 MB | 206894 bytes in |
| decode libzstd `-3` frame of the text | 1.06 s | 127 MB | 194276 bytes in |
| decode libzstd `-19` frame of the text | 1.02 s | 128 MB | 149901 bytes in |
| decode libzstd `-3` frame of random bytes (raw blocks) | 1.11 s | 127 MB | 1048613 bytes in |
| `compress` the text (checked) | 3.1 s | 252 MB | 309366 bytes out (29.5%) |
| `compress_unchecked` the text, then decode it | 3.2 s | 146 MB | 309366 bytes out |
| `compress` random bytes (checked) | 2.1 s | 319 MB | 1048613 bytes out (raw blocks) |

The compressor's frames are about 1.6 times libzstd `-3`'s on text: its
literals are raw (no Huffman coding) and its tables predefined. There is no
length limit but memory: the decoder's loops are tail-recursive and its
window an `Array`. `check.bend` compresses and decodes 100 KB as a
regression test.

A frame's content size field can say up to 2^64 - 1 bytes, but a native
build holds a `Nat` only up to 2^48 - 1 (a larger one stops the program).
So a content size of 2^48 or more is read as 2^48 - 1 (`frm.fcs_le` in
`frame.bend`). No frame that this decoder can finish produces that many
bytes, so this changes no answer: a single-segment frame with such a size
still fails with `WindowTooLarge`, and any other frame with `BadContentSize`
(`check.bend` decodes one of each).

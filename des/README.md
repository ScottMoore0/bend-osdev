# bend-osdev-des

DES (FIPS 46-3) and Triple DES (TDEA, NIST SP 800-67), 64-bit block ciphers on cipher-core's `LcBlock64`, with cipher-core's ECB and CBC (`modes64.bend`) over them. Triple DES is built from DES, so both are in this package (`tdes.bend` uses DES's key schedule directly).

The directory is `des` and the entry file `des/des.bend`; the hub name is `bend-osdev-des`. It is one of the packages split from bend-osdev-legacy-ciphers@0.1.0.0, which they supersede (that version stays on the hub as it was): cipher-core (what the ciphers share, and the 64-bit modes) and one package per cipher.

**DES and Triple DES are here for compatibility**: to read and write data that old formats, disks and protocols already hold. DES's 56-bit key is broken by exhaustive search; Triple DES is deprecated (NIST SP 800-131A Rev. 2 disallows it for encryption after 2023, and SP 800-67 Rev. 2 limits a key bundle to 2^20 blocks), and its 64-bit block has a birthday bound at 2^32 blocks. None of the code here is constant-time (see Side channels).

## Specifications

Written from the public specification only; no implementation's source was read.

* **DES:** FIPS PUB 46-3, *Data Encryption Standard* (1999): the initial
  permutation, the cipher function f (E, the S-boxes S1 to S8, P), the key
  schedule (PC-1, PC-2, the shifts), and the inverse permutation. Test
  vectors: NIST SP 800-17, *Modes of Operation Validation System* (1998),
  Table 1 (variable plaintext) and Table 2 (variable key).
* **Triple DES (TDEA):** NIST SP 800-67 Rev. 2, *Recommendation for the
  Triple Data Encryption Algorithm Block Cipher* (2017): E_K3(D_K2(E_K1(P)))
  and its inverse, keying options 1 and 2. Test vector: the worked example in
  SP 800-67 Rev. 1 (2012), Appendix B ("The qufck brown fox jump", keying
  option 1).

The test vectors were checked against the model in `ref/model.py` and Python's `cryptography` before they became laws or `check.bend` lines.

## Files

| File | Holds |
|---|---|
| `des.bend` | DES |
| `tdes.bend` | Triple DES, on des.bend |
| `gen/vectors.py` | the generator of the vector laws in `LAWS.bend`, their proofs in `PROOF.bend`, and `check.bend`'s `main` and expected `#|` lines, from `ref/model.py`; `python3 gen/vectors.py` rewrites them, `--check` checks they are up to date |
| `gen/proof.py` | the generator of `PROOF.bend`'s region "bits" (DES's IP and IP^-1 undo each other, on the block's 64 bits); the same two modes |
| `ref/` | the differential test (`run.sh`, `gen.py`, `model.py`) |

The generated regions lie between `# BEGIN GENERATED by gen/<script>.py: <name>` and `# END GENERATED: <name>` lines; everything outside them is written by hand. After changing the vector laws, run `gen/vectors.py`.

## Public interface

The key type is opaque: built by the cipher's `key` functions from the raw key, used only through the cipher's defs. Every fallible function answers `Result<&2, &2, LcError, A>` with cipher-core's `LcError`: `LcBadKeyLength{got}` for a key of a length the cipher does not take (DES: 8; 3DES: 16 or 24 bytes); the 64-bit modes add `LcBadIvLength` and `LcNotBlockMultiple`.

**`des.bend`**

| Def / type | Meaning |
|---|---|
| `LcDesKey`, `LcDes.key(o)` | an 8-byte key (the parity bits are ignored, as FIPS 46-3 says); opaque |
| `LcDes.encrypt(k, b)`, `LcDes.decrypt(k, b)` | one block |

**`tdes.bend`**

| Def / type | Meaning |
|---|---|
| `LcTdesKey`, `LcTdes.key(o)` | 24 bytes (keying option 1) or 16 bytes (keying option 2, K3 = K1); opaque |
| `LcTdes.key3(o)`, `LcTdes.key2(o)` | exactly option 1, exactly option 2 |
| `LcTdes.of_des(k1, k2, k3)` | the bundle of three DES keys (any keying, option 3 included) |
| `LcTdes.encrypt(k, b)`, `LcTdes.decrypt(k, b)` | one block |

Everything else (`des.*`, `tdes.*`, `LcDesHalves`, `LcDesRk`, `LcDesSp`) is
internal.

## With the 64-bit modes

the 128-bit modes are written for 128-bit blocks, so a 64-bit cipher uses
cipher-core's `modes64.bend` instead: ECB and CBC on `LcBlock64`, the cipher
as template arguments:

```
import ../cipher-core/modes64.bend as X
import ../des/tdes.bend as C

X.Lc64.cbc_encrypt(~C.LcTdesKey, ~C.LcTdes.encrypt, k, iv, m)
X.Lc64.cbc_decrypt(~C.LcTdesKey, ~C.LcTdes.decrypt, k, iv, c)
```

For padding, pkcs7's `Pkcs7.pad(8n, m)` and `Pkcs7.unpad(8n, m)` take
an 8-byte block size. crypto's ECB, CBC, CTR, PCBC and CBC-CS3 run over the
cipher too (crypto proves the ECB, CBC and PCBC round trips over it).

## Extension points

* **Any mode over these ciphers:** they are `modes64.bend`'s template
  arguments (cipher-core), and crypto's; a new mode takes `~K`, `~enc`,
  `~dec` and never looks inside the key.
* **Key bundles:** 3DES keying option 1 or 2 by length (or `key3` / `key2`
  to name it), or any three DES keys with `LcTdes.of_des`.
* **Replaceable internals:** the key types are opaque, so the round-key list
  and the SP tables can change without touching a caller. DES is IP, a list
  of Feistel rounds, the swap and IP^-1, decryption the steps undone in
  reverse order; a faster implementation (combined tables, bit-sliced
  permutations) can go behind the same defs, tied to these by the vectors and
  the differential test.
* **Not here yet:** DES weak-key detection (FIPS 74's weak and semi-weak keys,
  which the kernel can refuse).

## Laws

`LAWS.bend` (14 laws).

**For every input:**

* `des_round_trip`, `des_round_trip_dual`: for every DES key and every block,
  decryption undoes encryption and encryption undoes decryption;
* `tdes_round_trip`, `tdes_round_trip_dual`: the same for every 3DES key bundle
  (any three DES keys), from DES's two laws;
* `des_ecb_round_trip`, `des_cbc_round_trip`, `tdes_ecb_round_trip`,
  `tdes_cbc_round_trip`: cipher-core's 64-bit modes undo themselves on blocks,
  for every key, IV and list of blocks;
* `des_cbc_octets_round_trip`, `tdes_cbc_octets_round_trip`,
  `des_ecb_octets_round_trip`, `tdes_ecb_octets_round_trip`: the same on bytes,
  for every message given as the bytes of a list of blocks,
  `Lc64.octets_of(bs)`, and every 8-byte IV (every whole-block message has
  that form, but no law states it).

**Vectors** (proved by computation): the refusals of a 7-byte DES key and an
8-byte TDEA bundle. SP 800-17's (DES) and SP 800-67's (3DES) vectors run
compiled in `check.bend` instead: the checker proves them (in seconds each),
but they run past the `--verdict` kernel's evaluation budget, and a package
whose proofs pass `--verdict` is worth more than vectors that `check.bend`
runs anyway.

How the round trips are proved: DES is IP, a list of Feistel rounds, the
swap and IP^-1; each round is undone by XOR whatever the round function is
(cipher-core's `u32_xor_cancel`), and IP and IP^-1 undo each other on the
block's 64 symbolic bits (`gen/proof.py`), so no proof evaluates the cipher.
3DES's laws follow from DES's. The modes' laws are an induction over the
structural forms of ECB and CBC with the cipher's law at each block, carried
to the public block and byte layers by cipher-core's `modes64_ecb_blocks`,
`modes64_cbc_blocks`, `modes64_ecb_octets` and `modes64_cbc_octets` (and
`block64_xor_cancel` for CBC's chaining).

The proofs need nothing from another package beyond its public interface and laws: cipher-core's laws (above).

## Tests

* `check.bend` runs SP 800-17's five DES vectors both ways (encryption,
  then decryption back), SP 800-67's three-block example in ECB and CBC with
  keying options 1 and 2, 3DES CBC over 16 KB both ways, and the 64-bit modes'
  two refusals (a 7-byte IV, a message that is not whole blocks).
* `ref/run.sh` compares DES (as TripleDES with three equal keys) and 3DES (both keying options) against Python's `cryptography` (OpenSSL), and both against `ref/model.py`, on random keys, blocks and messages, each a block both ways and a CBC message both ways. **`ref/model.py` was written here from the specification, by the same author as this package**, and is first checked against the specification's published vectors. When `cryptography` is missing, `run.sh` compares with the model alone and says so; it exits 77 only when `python3` is missing.

## Speed

Measured on Bend 2.0.37, native builds (`bend file.bend -o prog`), WSL2, before the split (the code is unchanged):

| Run | Time | Notes |
|---|---|---|
| DES | 49 us per 8-byte block | IP and IP^-1 are computed on bits (for the proofs) |
| 3DES | about 160 us per block | three DES |
| 3DES, CBC through modes64.bend, 1 MB both ways | 43.3 s, 224 MB peak |  |

The cipher builds its lookup tables when its key is made and keeps them in the key (Bend 2.0.37 recomputes a table def at every call). Messages have no length limit beyond memory: every loop over blocks or bytes is a tail call.

## Side channels

The S-boxes are table lookups (trees walked by the bits of a secret index). None of this is constant-time, and Bend's runtime promises nothing about running time anyway. Do not use this package where timing attacks matter.

## Dependencies

`DEPS`: `bytes` (`Octets`); `cipher-core` (the error type `LcError`, the word helpers and tables the cipher is built from, and its laws in the proofs: XOR undone and the rest).

# bend-osdev-sm3

SM3 (GB/T 32905-2016), the Chinese national hash, streaming (init, update,
final) and one-shot, through md-engine's Merkle–Damgård engine. sm2's
signatures take it as their default hash.

The directory is `sm3` and the entry file `sm3/sm3.bend`; the hub name is
`bend-osdev-sm3`. It is one of the packages split from
bend-osdev-hashes@0.1.0.0, which they supersede (that version stays on the
hub as it was): md-engine (the Merkle–Damgård engine and what the hashes
share) and one package per hash.

## Specifications

Written from the public specification only; no GPL source was read.

* **SM3:** GB/T 32905-2016, *Information security techniques — SM3
  cryptographic hash algorithm*; in English, draft-shen-sm3-hash-01, S.
  Shen and X. Lee, *SM3 Hash Function* (February 2014), sections 3.1 to
  3.3 and examples 1 and 2.

**SM3 and bend-collections.** bend-collections-laws-crypto@1.0.0.0 (an
allowed hub package) was searched file by file for SM3 (and MD4, MD5,
SHA-1, RIPEMD-160, Streebog and PBKDF2) before anything was written: it has
none of them, so SM3 is written here rather than adapted.

## Files

| File | Holds |
|---|---|
| `sm3.bend` | SM3: `HsSm3.*` |
| `gen/spec.py` | the specification's tables (the initial value and the constants T_j (draft-shen-sm3-hash-01, sections 3.1 to 3.3)), with their sources |
| `gen/rounds.py` | writes the unrolled compression function (the region "sm3" of `sm3.bend`) from `spec.py` |
| `gen/laws.py` | writes `LAWS.bend` and `PROOF.bend` |
| `gen/check.py` | writes `check.bend` and its expected output |
| `ref/model.py`, `ref/gen.py`, `ref/run.sh` | the differential test (Tests below) |

`python3 gen/<script>.py` rewrites what a generator writes, and `--check`
checks it is up to date. The generated region lies between `# BEGIN
GENERATED by gen/rounds.py: sm3` and `# END GENERATED: sm3`; everything
else in `sm3.bend` is written by hand.

Bend imports do not re-export: import md-engine's `md-engine.bend` beside
`sm3.bend` to name the state and chaining-value types.

## Public interface

| Def | Meaning |
|---|---|
| `HsSm3.init()` | the state before any byte (md-engine's `HsMdState<HsW8>`) |
| `HsSm3.update(s, o)` | the state after more bytes (`Octets`), in any pieces |
| `HsSm3.final(s)` | the digest of the bytes so far (32 bytes) |
| `HsSm3.digest(o)` | the digest in one call (`final(update(init(), o))`) |
| `HsSm3.compress(cv, block)` | the compression function on one 64-byte block (a list of bytes) |
| `HsSm3.iv()` | the initial chaining value |

Everything else (`hs.sm3.*`) is internal. The hash, as crypto's hash
interface takes it:

```
~Hs.HsMdState<Hs.HsW8>, ~64n, ~32n, ~HsSm3.init(), ~HsSm3.update, ~HsSm3.final, ~HsSm3.digest
```

## Extension points

* **The compression function is replaceable.** `HsSm3.compress` is one def
  written from the tables in `gen/spec.py`; a faster one (a different
  unrolling) can replace it, and the laws hold for every compression
  function (md-engine's `md_streaming`).
* **Any user of a hash:** the defs above are the template arguments
  crypto's hash interface takes, so HMAC, HKDF and PBKDF2 (crypto) run over
  SM3 with no adapter.
* **The engine and its types** are md-engine's (its README, Extension
  points).

## Laws

`LAWS.bend` (written by `gen/laws.py`) has 7 laws.

**For every input**, with no hypothesis:

* `sm3_streaming`: update over `a ++ b` is update over `a`, then `b`, from
  every state (md-engine's `md_streaming` at SM3's defs);
* `sm3_split` and `sm3_split3`: the streaming digest of any split into
  two or three pieces is the one-shot digest;
* `sm3_length`: the final digest of every state has 32 bytes
  (md-engine's `w8_be_length` at the chaining value after the padding), and
  `sm3_digest_length`: so has the one-shot digest of every message.

**Vectors**, by computation: the specification's two examples
(draft-shen-sm3-hash-01, examples 1 and 2), `sm3_example_1` and `_2`.

**Not laws, and why.** The digest's agreement with the algorithm's
definition for every message: a hash has no specification beyond its
algorithm, so the vectors and the differential test hold it.

The proofs need nothing from another package beyond its public interface and
laws: md-engine's `md_streaming` and `w8_be_length`.

## Tests

* `check.bend` (written by `gen/check.py`): the two examples through the
  public interface, the digest in one call and in three pieces through
  init/update/final. The expected lines are the specification's values.
* `ref/run.sh` (27 cases with the default seed): SM3 on 27 message lengths
  (around every block boundary up to three blocks, and 1000 and 4103 bytes),
  whole and cut into three pieces at random points, against Python's
  `hashlib` where OpenSSL provides SM3 (here it does), and otherwise
  `ref/model.py` (written here, from the specification, checked against the
  examples and against hashlib where it can be), which the last line then
  names.
* The crypto package's tests run SM3 through its hash interface, and HMAC
  and PBKDF2 over it, against Python's `hmac` and `hashlib.pbkdf2_hmac`
  (crypto/README.md).

## Sizes

Native builds (Bend 2.0.37, WSL2), a 1 MB pseudo-random message (its
building included), measured before the split (the code is unchanged): 0.12
s and 84 MB. Updates are tail calls over the bytes, so a message has no
length limit beyond memory.

## Notes on use

* None of this code is constant-time, and Bend's runtime promises nothing
  about running time.

## Dependencies

`DEPS`: `bytes` (`Octets`) and `md-engine` (the engine, the chaining-value
types and word helpers, and its laws in the proofs). No hub package.
